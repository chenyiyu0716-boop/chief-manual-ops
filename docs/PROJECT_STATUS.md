# 项目现状

本文件记录 Chief 封档时的项目级真值。它不替代各项目仓库的最新状态文件。

## Julius

**定位：** 面向大众的知识与内容生产系统。传播入口可以借用大众兴趣，但内容内核必须把注意力从结果迁移到过程、判断、约束、代价和不可复制条件。

已固化的核心资产包括：

- Constitution：最高原则、边界和防漂移机制；
- Editorial Doctrine：选题、研究、叙事、AI 权限和发布标准；
- Knowledge Model：从原始问题到母题、过程样本、认知工具和多载体输出；
- First Experiment Plan：首轮内容实验。

治理边界：Owner 是主编；Chief 负责把主编判断转成任务与验收，不能替代主编决定选题或最终成稿。

下一阶段原则：不靠新增功能解决内容逻辑问题；先确保选题可追溯、问题真实存在、人物观点形成冲突，并能明确观众最后带走什么。

## Director

**定位：** 支持内容研究、生成、编辑、版本和知识沉淀的生产工作台。

当前主线是稳定化，不是扩展功能：

- 让系统健康状态反映真实调用、fallback 和失败；
- 修正模型协议与上传等真实生产故障；
- 保持可编辑、可恢复、可追溯的生产流程；
- 逐个隔离候选、独立复审，再决定是否集成；
- 不在生产脏树上直接开发，不把测试通过等同于部署完成。

封档时仍有候选改动处于 Chief 复审/集成门禁中，因此不能把“候选完成”写成“生产已修复”。

## Control Plane

**定位：** 定义任务治理、安全边界和证据契约。

已验证并保留的设计资产：

- 任务 schema 与项目注册；
- 队列、租约、状态转换和失败关闭；
- Chief-authored 验收命令；
- 官方执行报告和 REVIEW 停点；
- 独立 clone、无共享对象、内核级写白名单；
- 候选提交导入、回滚和基线守恒。

当前裁定：`DESIGN-ONLY / ARCHIVED`。自动执行器接入没有通过生产端到端验收，不再继续增加适配轮次，也不切换生产入口。

## Eval

**定位：** 通用 AI Agent 生产验收框架，首个垂类是 Deep Research Agent。

边界：

- 像体检一样检查单体 Agent 的交付健康；
- 输出完成项、缺口、阻断缺陷、人工返工和是否可进入下一环节；
- 多个 Agent 只是校准同一把尺子的样本；
- 不做排行榜、综合冠军、认证、持续监测或代运营；
- Phase 0 的成功条件是证明该框架能揭示普通质量分数无法表达的交付风险。

当前阶段：实验设计和双语报告骨架已形成；真实运行结论必须等真实实验和盲评完成后填写。

## Chief 自身

自动化方向封存后，Chief 进入 `MANUAL / ACTIVE`：

- 不常驻、不自动唤醒、不自动派发；
- 每个项目用独立 Codex 任务维护上下文；
- 需要方案时启动 Chief 任务，产出冻结任务书；
- 人工把任务书交给 Executor；
- Executor 交卷后再启动或回到 Chief 任务复审。

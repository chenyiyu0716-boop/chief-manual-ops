# 自动化实验复盘

## 实验目标

最初目标是让 Control Plane 自动接收任务、创建隔离工作区、调用市售 Agent CLI、生成候选提交和官方报告，并自动停在 REVIEW，随后由 Chief 复审。

## 已证明成立的部分

- 任务、项目、租约和状态机可以工作；
- 独立 clone 与 fail-closed 写边界可实施；
- 白名单外写入可以被内核拒绝；
- Executor 可以被限制为单提交并停在 REVIEW；
- 失败可以回滚到已知安全入口；
- Chief-authored 验收优于 Executor 自选验收。

这些能力作为设计资产保留。

## 为什么没有进入生产

### 执行器 A

在隔离 HOME 与沙箱中，无头调用出现网络/API 可达性不稳定；宿主连通不代表隔离执行路径可用。自动入口没有完成稳定的生产 E2E。

### 执行器 B

CLI 依赖桌面/Node 运行环境，在强隔离中出现启动或挂起问题。后续实验又发生调用预算与证据覆盖违规，相关验收被判 `INVALID`。

### 执行器 C

无头接口资格探针本身通过，但适配器实现未满足生产要求：白名单、真实输出契约、进程组回收、凭证清理、CLI 钉版本和测试事故判定均存在缺口。修订后仍不足以承担无人值守责任。

## 关键教训

1. CLI 存在不等于有稳定的 CI/headless 契约。
2. 一次 canary PASS 只能证明资格，不能证明生产适配器完成。
3. 宿主成功、curl 成功或登录状态正常，不能替代隔离路径真实验证。
4. 测试套件显示绿色，但若进程泄漏或 stderr 明确报错，仍应失败。
5. 删除 occupancy、数据库或日志不是 reset，而是拆除审计护栏。
6. 自动化收益必须高于为适配执行器持续放宽安全边界的成本。

## 封存裁定

自动执行器接入标记为 `DESIGN-ONLY / ARCHIVED`。不再为现有工具增加修复轮次，不部署、不切生产入口。

## 解封条件

只有满足以下任一条件，且 Owner 明确批准，才重新立项：

1. 执行器提供官方稳定的无头凭证、机器可判输出、无交互权限策略和可钉版本；
2. 新版本已在独立环境证明真实任务到 REVIEW、凭证清除与整组进程回收；
3. Owner 主动接受新的预算、风险和运维成本。

解封是一个新项目，不能把旧实验直接标绿后继续。
